# 발표 준비: 양식과 심사 기준에 맞춘 개요

각 발표 항목에 어떤 자료를 쓰면 되는지 정리했습니다. 괄호 안은 심사 가중치입니다.

## 중간 발표

| 발표 양식 | 심사 항목 | 쓸 자료 | 보여 줄 것 |
|---|---|---|---|
| 프로젝트 기획안 | 독창성 (30%), 문제 정의 및 기획 (20%) | [PLAN.md](PLAN.md) | 문제 정의 3가지, 기능 요구사항 11개, 차별점 표(기존 서비스 비교 열 추가) |
| AI 워크플로우 및 환경 설정 | AI 활용 계획 (40%) | [AI_WORKFLOW.md](AI_WORKFLOW.md) | 도구별 역할과 고른 이유, 파이프라인 그림(코드 → 품질 게이트 → 페르소나 시뮬레이션 → 문제 기록) |
| 초기 프롬프트 전략 | AI 활용 계획 (40%) | [PROMPTS.md](PROMPTS.md) 2절 v1~v2 | 서버가 프롬프트를 가진 이유(키 보호, 주입 방지), 구조화 출력, 직무 설계도 |
| 향후 계획 | 발표 (10%) | [PLAN.md](PLAN.md) 향후 계획 | 실제 AI로 반복 측정, 배포, 사용자 피드백 |

가중치가 가장 큰 "AI 활용 계획(40%)"에서는 도구를 나열하기보다, **AI가 만든 결과를 AI(페르소나 시뮬레이션)와 자동 검사로 다시 검증하는 순환 구조**를 강조하세요.

### 트러블슈팅 발표용 추천 사례

1. **꼬리질문이 0개였던 버그(3번)**: 시뮬레이션으로 발견하고, 요청 데이터를 재현하는 테스트로 원인을 찾은 과정이 논리적이다.
2. **계획과 경험을 구분하지 못한 면접관(4번)**: 목 면접관 버그를 고친 뒤 같은 규칙을 AI 프롬프트에도 옮겼다. 프롬프트 개선과 연결된다.
3. **AI 응답 하나가 면접 전체를 멈춤(9번)**: 일부러 깨진 응답을 주는 가짜 서버로 재현했다.
4. **TTS 서비스 연쇄 장애(2, 13, 14, 15번)**: 크레딧 부족, 유료 플랜 제한, 계정 차단, 스키마 불일치를 차례로 겪으며 대체 구조를 만든 이야기.
