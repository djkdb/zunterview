# 트러블슈팅 기록

개발하면서 부딪힌 문제를 `증상 → 원인 → 디버깅 과정 → 해결 → 재발 방지` 순서로 남깁니다. 새 문제는 맨 아래에 같은 형식으로 추가합니다(번호를 이어서 매깁니다). 관련 커밋은 `git show <해시>`로 볼 수 있습니다.

분류: `[AI 출력]` 모델이나 목(mock) 면접관이 이상한 말을 함 · `[연동]` 외부 API · `[빌드/환경]` 개발 환경 · `[UI]` 화면

## 1. [빌드/환경] 고친 코드가 실행에 반영되지 않음

- **증상**: TypeScript를 고치고 테스트를 돌려도 예전 동작이 그대로 나왔다. 화면도 마찬가지였다.
- **원인**: `npx tsc -b`를 한 번 실행해서 `src/`, `shared/` 안에 `.js` 컴파일 결과가 생겼다. Vite와 Vitest는 같은 이름이면 `.ts`보다 `.js`를 먼저 읽어서, 수정 전 코드가 계속 실행됐다.
- **디버깅**: 디버그 로그를 넣었는데 출력되지 않았다. 그래서 실제로 어떤 파일이 실행되는지 의심했고, `.ts` 옆에 같은 이름의 `.js`가 있는 것을 찾았다.
- **해결**: `.gitignore`에 `src/**/*.js`, `shared/**/*.js`를 추가했다(b9e2043). 실수로 커밋된 결과물은 지웠다(3efa25a). 남은 파일은 `git clean -f -X -- src shared`로 지운다.
- **재발 방지**: 타입 검사는 `npm run typecheck`(`--noEmit`)로만 한다.

## 2. [연동] Fish Audio 음성이 503으로 실패

- **증상**: 면접관 음성이 나오지 않고 브라우저 기본 음성으로 바뀌었다. 서버는 503만 돌려줬다.
- **원인**: 서버가 Fish의 오류를 503 하나로 뭉뚱그려서 진짜 이유가 보이지 않았다. 로그를 고치고 보니 `402 Insufficient API credit`이었다. Fish Audio는 웹 앱 크레딧과 API 크레딧이 따로다.
- **디버깅**: 키가 틀린 경우와 잔액이 없는 경우를 구분할 수 없었다. 그래서 상태 코드와 응답 본문을 서버 로그에만 남기게 했다(24ebc68).
- **해결**: 실패 이유를 로그로 남기고, 실패하면 브라우저 음성으로 이어서 읽게 했다. 이후 TTS를 여러 서비스로 늘렸다(14번 참고).
- **재발 방지**: 외부 API가 실패하면 상태 코드와 응답 본문을 서버 로그에 남긴다. 클라이언트에는 노출하지 않는다.

## 3. [AI 출력] 꼬리질문이 한 번도 나오지 않음

- **증상**: "같은 답변 반복" 감지를 추가한 뒤로 목 면접관이 꼬리질문을 전혀 하지 않았다.
- **원인**: 꼬리질문 요청의 `history`에는 방금 답한 턴이 이미 들어 있다. 그래서 "이전 답변과 같은가" 검사가 매번 자기 자신과 비교해 항상 반복으로 판정됐다.
- **디버깅**: 페르소나 5명으로 면접을 끝까지 돌렸는데 꼬리질문이 0개였다. 그래서 요청 데이터를 그대로 재현하는 테스트를 만들었다.
- **해결**: 현재 턴을 뺀 다른 질문의 답변하고만 비교하도록 했다(`earlierAnswers`, f83bcae).
- **재발 방지**: 앱이 실제로 만드는 요청 모양 그대로 회귀 테스트를 만든다.

## 4. [AI 출력] 계획만 말했는데 "어떻게 해결하셨나요?"를 물음

- **증상**: "장애가 생기면 원인을 찾아 기여하고 싶습니다"라고 답했는데 "그 장애의 원인은 어떻게 파악하셨나요?"라는 꼬리질문이 나왔다.
- **원인**: 키워드("장애")만 보고 꼬리질문을 골랐다. 실제로 한 일과 하고 싶은 일을 구분하지 않았다.
- **디버깅**: 소프트웨어학부 졸업생 페르소나로 CLI 면접을 돌리다 발견했다.
- **해결**: 그 문장이 과거형인지(`했/었/았/였습니다`), 바람이나 계획인지(`싶습니다/겠습니다/예정`)를 보고, 실제로 한 일일 때만 경험형 꼬리질문을 하게 했다(`mentionedAsDone`, 4f0d089). 계획에는 "그 방법이 통하지 않으면?" 같은 검증 질문을 한다(960cc6d). AI 프롬프트에도 같은 규칙을 넣었다(b43e83d).
- **추가 발견**: "팀에서 일하고 싶었습니다"는 `었습니다`가 들어 있어 과거형으로 잘못 판정됐고, 지원동기 답변에 "그중 본인이 직접 해결한 부분은?"을 물었다. `싶었습니다`를 예외로 처리했다(b80a5ef).

## 5. [AI 출력] 다른 뜻의 단어를 주제로 착각

- **증상**: "퍼포먼스 마케터"에게 성능 문제 꼬리질문을, "회전 속도"(재고)에 느린 시스템 질문을 했다. "공정 엔지니어"로 지원한 LG화학 지원자에게 반도체 CMP 질문이 나왔다.
- **원인**: 단어 단위 매칭이라 문맥을 보지 않았다. "공정"이 반도체 공정 하나에 묶여 있었다.
- **해결**: 성능 주제는 처리·응답·로딩 속도일 때만 잡게 했다. "공정"·"공정 엔지니어"는 넓은 말로 분류해 공정기술·화공·반도체·배터리·생산기술 중 고르게 했다(4761170, e4f8d84).
- **재발 방지**: 직무 검색어에 대한 단위 테스트(`shared/roles.test.ts`)를 늘렸다.

## 6. [AI 출력] 면접실에서 할 수 없는 질문

- **증상**: "이력서에 적은 JWT 방식을 설명해 주세요", "화이트보드에 그려 주세요", "지금 라이브 코딩으로…" 같은 질문이 나왔다. 서류를 받지도 않았는데 이력서를 언급했다.
- **원인**: 공개 후기에서 온 질문 은행과 AI가 실제 면접장 상황을 그대로 가져왔다.
- **해결**: 누가 질문을 만들었든(AI, 직무 은행, 기업 은행) `shared/questionRules.ts`의 `unaskable()`로 걸러, 다시 만들거나 목 은행 질문으로 대체한다(b43e83d). 서류 기반 면접이 생긴 뒤에는 서류를 제출했을 때만 이력서 언급을 허용한다(b80a5ef).
- **추가 발견**: 자기소개 반복 금지 규칙(`자기\s?소개`)이 "자기소개서"까지 잡았다. 부정 전방탐색 `자기\s?소개(?!서)`으로 고쳤다.

## 7. [AI 출력] 상황 질문에 맞게 답했는데 "질문과 다른 답"으로 감점

- **증상**: "트래픽이 몰리면?"이라는 질문에 부하 테스트·캐시·큐로 답했는데 질문을 피했다고 판정됐다.
- **원인**: 질문 속 단어가 답변에 없으면 회피로 봤다. 상황 질문은 다른 말로 답하는 것이 정상이다.
- **해결**: 회피 검사를 지식형 질문(직무 지식, 기술, 수치, 분석, 산업, 직무 이해)에만 적용했다(960cc6d).

## 8. [AI 출력] 매 답변 같은 반응, 같은 칭찬

- **증상**: 좋은 답변마다 "좋습니다. 핵심이 잘 전달됐습니다."가 반복됐다.
- **원인**: 반응 문구를 고르는 시드가 질문 수에만 묶여 있었다. 문구 자체도 상투적이었다.
- **해결**: 턴마다 문구를 돌려 쓰게 했고(4f0d089), humanizer 스킬 기준으로 문구를 실제 면접관 말투로 바꿨다(5e0fd8c). AI 프롬프트에는 상투어와 줄표를 금지하는 `PLAIN_VOICE` 규칙을 넣고, 응답에 남은 줄표는 서버에서 지운다.

## 9. [연동] AI 응답 하나가 깨지면 면접 전체가 멈춤

- **증상**: 모델이 형식에 맞지 않는 분석을 돌려주면 오류 화면이 떠서 면접을 이어 갈 수 없었다.
- **디버깅**: 일부러 깨진 응답을 돌려주는 가짜 Anthropic 서버를 로컬에 띄워 재현했다.
- **해결**: 실패한 호출 하나만 목 면접관이 대신 답하고 면접은 계속 진행한다. 세 번 연속 실패하면 목 모드로 전환한다(6193e6c).

## 10. [빌드/환경] 백그라운드 서버를 끄다가 작업 셸까지 꺼짐 (exit 144)

- **증상**: 서버를 재시작하려고 `pkill -f "server/index.ts"`를 실행하자 명령을 실행한 셸 자체가 종료됐다.
- **원인**: `pkill -f`는 명령줄 전체를 보고 일치하는 프로세스를 죽인다. 그 문자열을 담은 셸 명령도 같이 죽었다.
- **해결**: `ps`로 PID를 찾아 `kill <PID>`로 끈다.

## 11. [UI] 휴대폰에서 면접관 얼굴이 잘리고 화면이 겹침

- **증상**: 화면 높이가 낮으면 면접관 머리가 잘렸다. 375px 폭에서는 지원번호가 문항 표시와 겹쳤다.
- **해결**: 사진 속 얼굴 위치를 기준으로 보이는 영역을 정하게 했다(`useViewBox`). 좁은 화면에서는 면접관을 크게 보여 주고, 400px 이하에서는 지원번호를 숨겼다(4a66f3c, e4f8d84).

## 12. [AI 출력] 기업 인재상이 "미션, 핵심가치…"로 나열됨

- **증상**: 평가표에 "서울아산병원의 인재상: 미션, 핵심가치, 간호부 미션…"처럼 항목 이름만 나왔다.
- **원인**: 기업 데이터의 인재상 형식이 기업마다 달랐다(`"인재제일"` 단어형과 `"핵심가치: 나눔과 배려 · 정직과 신뢰"` 설명형).
- **해결**: "가치/인재상" 항목은 값을 나눠 쓰고, 미션 문장은 빼는 `talentWords()`를 만들었다(5e0fd8c).

## 13. [연동] ElevenLabs에 추가한 한국어 목소리가 402

- **증상**: Voice Library에서 계정에 추가한 한국어 목소리로 요청하자 `402 paid_plan_required`가 돌아왔다.
- **원인**: 무료 플랜은 Voice Library 목소리를 API로 쓸 수 없다.
- **해결**: 자리마다 모든 계정에 있는 기본 목소리를 예비로 두었다. 402나 `voice_not_found`가 오면 그 목소리는 서버를 재시작할 때까지 건너뛰고 기본 목소리로 읽는다(d39f92d). 유료 플랜으로 바꾸면 코드 수정 없이 한국어 목소리가 나온다.

## 14. [연동] Typecast가 무료 계정을 차단 (403 UNUSUAL_ACTIVITY_DETECTED)

- **증상**: Typecast 연동 직후 모든 요청이 `403 UNUSUAL_ACTIVITY_DETECTED`로 거절됐다.
- **원인**: 목소리를 고르려고 후보 샘플 11개를 짧은 시간에 연달아 만들었다. 클라우드 서버 IP에서 요청이 몰리자 무료 계정 남용으로 감지된 것으로 보인다.
- **해결**: 차단된 동안은 ElevenLabs가 대신 읽는다(서비스 순서: Typecast → ElevenLabs → Fish Audio). 401·402·403으로 계정을 거절한 서비스는 10분 동안 건너뛰어, 문장마다 다시 요청해 상황을 악화시키지 않게 했다(f43e0cf).
- **재발 방지**: 유료 API를 시험할 때는 요청을 몰아서 보내지 않는다. 샘플은 필요한 만큼만 만들고 간격을 둔다.
- **상태**: 미해결. 같은 날 서버를 다시 띄워 한 번 더 요청했지만 여전히 403이었고, ElevenLabs가 대신 읽었다. 계정 쪽에서 차단이 풀려야 한다.

## 15. [연동] 새 TTS 서비스를 추가하자 클라이언트가 조용히 신경망 음성을 끔

- **증상**: 서버 `/api/health`가 `tts: "elevenlabs"`를 돌려주는데 브라우저는 기본 음성을 썼다.
- **원인**: 공유 스키마(`HealthSchema`)의 `tts` 값이 `"fish"`만 허용하는 enum이었다. 검증에 실패하자 클라이언트가 TTS가 없는 것으로 처리했다.
- **해결**: enum에 새 서비스를 추가하고, 클라이언트는 값이 있기만 하면 신경망 음성을 쓰게 했다(26be91d).
- **재발 방지**: 서버 응답 형식을 바꿀 때는 `shared/schemas.ts`도 같이 바꾼다.

## 16. [빌드/환경] 자동 승인 모드에서 일부 파일 수정이 거부됨

- **증상**: UI 정리 중 `AnswerInput.tsx`, `TopBar.tsx`, `InterviewHeader.tsx` 수정이 Claude Code의 자동 승인 분류기에 의해 "Self-Modification"으로 거부됐다.
- **원인**: 바로 전에 `.claude/skills/`에 스킬을 설치한 직후라, 분류기가 에이전트 자기 수정과 관련된 작업으로 판단한 것으로 보인다.
- **해결**: 우회하지 않고 사용자에게 상황을 설명했다. 명시적으로 승인받은 뒤 진행했다(456b0c9).

## 17. [빌드/환경] 1번 문제가 다시 발생: 새 필드가 테스트에서 보이지 않음

- **증상**: 서류 문장에 `context` 필드를 추가했는데, 서류-답변 비교 테스트에서 역할 불일치가 계속 "일치"로 나왔다.
- **원인**: 1번과 같다. 예전에 생긴 `shared/documents.js`가 남아 있어서 Vitest가 수정 전 코드를 읽었다.
- **디버깅**: 코드상으로는 맞는데 결과가 다르면 실행되는 파일을 먼저 의심한다는 1번의 교훈을 그대로 적용했다. `npx tsc -p tsconfig.json`으로 `.js`를 다시 만든 뒤 테스트가 통과했다.
- **해결**: 임시 조치. 남은 `.js`를 지우는 근본 해결(`git clean -f -X -- src shared`)은 아직 하지 않았다.
- **교훈**: 같은 문제가 두 번 나왔으니 근본 원인(남은 `.js`)을 지워야 한다.

## 18. [AI 출력] 서류-답변 비교가 기간을 핵심 수치로 착각

- **증상**: "3개월 동안 사용자 1,200명을 모았습니다"를 확인할 때 "서류에 쓴 3개월를 답변에서 설명하지 않았습니다"라고 나왔다. 숫자도 틀렸고 조사도 틀렸다.
- **원인**: 문장에서 첫 번째 숫자를 골랐다. 조사는 "를"로 고정돼 있었다.
- **디버깅**: 서류를 낸 페르소나로 면접을 끝까지 돌리고 평가표를 읽다가 발견했다.
- **해결**: 기간(개월·주·일·시간)보다 결과 수치를 먼저 고르고, 단위를 읽는 소리에 맞춰 을/를, 이라고/라고를 고른다. 회귀 테스트를 추가했다.

## 19. [빌드/환경] 운영 서버가 면접관 사진을 이미지가 아닌 파일로 보냄

- **증상**: 사진은 화면에 나왔지만, 운영 모드 서버가 `.webp` 사진을 `application/octet-stream`으로 보내고 있었다.
- **원인**: 정적 파일 서버의 MIME 표에 `.webp`, `.mp3`, `.webmanifest`가 없었다. 브라우저가 이미지 내용을 보고 추측해서 겉으로는 문제가 없어 보였다.
- **디버깅**: 배포 이미지를 흉내 낸 폴더에서 운영 모드로 띄우고 응답 헤더를 하나씩 확인하다가 발견했다(`curl -w "%{content_type}"`).
- **해결**: MIME 표에 해당 형식을 추가했다. 같은 작업에서 HTML 응답에 Content-Security-Policy와 `X-Frame-Options: DENY`도 붙였다.
- **재발 방지**: 새 정적 파일 형식을 추가하면 운영 모드에서 응답 헤더를 확인한다.

## 20. [빌드/환경] 개발 환경에서 Docker 이미지를 빌드할 수 없음

- **증상**: `docker build`가 "failed to connect to the docker API"로 실패했다.
- **원인**: 클라우드 개발 환경에 Docker 클라이언트는 있지만 데몬이 없다.

## 21. [빌드/환경] 1번 문제가 세 번째로 발생: 고친 화면이 빌드에 반영되지 않음, 근본 해결

## 24. [AI 출력] 목 면접관이 "3개월"을 "'3개'이라는 수치"로 인용

- **증상**: 예상 꼬리질문을 확인하다가 "말씀하신 '3개'는 어떻게 측정하거나 확인하셨나요? '3개'이라는 수치를 제시했지만…"이 나왔다. 답변은 "출시 후 3개월 동안 학생 1,200명이 가입했고"였다.
- **원인**: 수치를 찾는 정규식에 "개월"이 없어 "3개월"의 "3개"까지만 잡혔고, 문장에서 처음 나온 숫자를 그대로 골랐다. 조사도 "이라는"으로 고정돼 있었다.
- **디버깅**: 서류를 낸 페르소나(minsu)의 평가표에서 문항 카드를 열어 발견했다. 18번(서류 비교의 "3개월를")과 같은 종류의 문제였다.

- **재발 방지**: 수치를 다루는 규칙은 기간과 결과를 구분해야 한다. 18번과 24번이 같은 실수다.

## 25. [UI] 모바일 첫 화면 메뉴가 화면 밖으로 밀림

- **증상**: 390px 화면에서 첫 화면 상단 메뉴가 "기업별 면접, 면접 기록, 자…"까지만 보이고 잘렸다. 넓은 화면에서만 보이게 한 "자기소개 연습" 버튼이 모바일에서도 나왔다.
- **원인**: 버튼 컴포넌트가 기본으로 `inline-flex`를 갖고 있는데 바깥에서 `hidden md:inline-flex`를 덧붙였다. 두 클래스가 모두 display를 정하므로 CSS에서 나중에 생성된 쪽이 이겨서 `hidden`이 적용되지 않았다. "답변 노트" 버튼도 같은 방식이었다.
- **디버깅**: 면접 준비 플랜을 모바일에서 확인하다 스크린샷에서 발견했다. 화면 폭별로 보이는 메뉴 버튼 목록을 출력해 확인했다.
- **해결**: 버튼을 `<span className="hidden md:contents">`로 감싸 바깥에서 숨긴다. 수정 뒤 390px에는 메뉴 2개, 700px에는 3개, 1440px에는 4개가 나온다.
- **재발 방지**: display가 정해진 컴포넌트는 className으로 숨기지 말고 감싸서 숨긴다.

## 26. [외부 모델] VoxCPM2: 목소리 설계가 묘사한 성별을 따르지 않음, CPU에서는 느림

- **증상**: VoxCPM2의 목소리 설계로 면접관 4명의 기준 음성을 만들었는데, "30대 여성 인사팀 책임"으로 묘사한 목소리의 음높이(중앙값 146Hz)가 "40대 남성 면접위원장"(173Hz)보다 낮았다. 첫 시험에서는 "40대 남성"이 231Hz로 나왔다. 보통 남성 목소리는 85~155Hz, 여성은 165~255Hz 정도다.
- **원인**: 확인하지 못했다. 묘사를 한국어로 썼을 때 성별을 제대로 따르지 않았고, 영어로 쓰니 대체로 따랐다. 같은 묘사에서도 시드에 따라 결과가 달랐다(실무 면접관 묘사 하나는 216Hz로 나옴).
- **디버깅**: 이 환경에서는 소리를 들을 수 없어서 두 가지를 측정했다. faster-whisper(small)로 받아쓰기해 내용이 맞는지 확인했고, librosa의 pYIN으로 음높이 중앙값을 쟀다. torchaudio의 간단한 음높이 검출은 값이 크게 흔들려서 pYIN으로 바꿨다. 받아쓰기는 모든 음성에서 입력 문장과 거의 같았다.
- **해결**: 묘사를 영어로 바꾸고 자리마다 후보를 2개씩 만들어, 음높이가 묘사와 맞고 받아쓰기가 정확한 것을 골랐다(면접위원장 126Hz, 인사팀 239Hz, 실무 124Hz, 안내 직원 250Hz). 이 기준 음성을 복제해 앱에서 읽은 질문은 여성 자리가 239Hz·281Hz, 남성 자리가 159Hz·156Hz였다. 남성 자리는 기준 음성보다 높게 나왔다.
- **속도(미해결)**: GPU가 없는 이 환경(CPU 4코어, 메모리 15GB)에서 모델 로딩 86초, 생성은 음성 1초에 약 4.3초(목소리 설계), 앱을 거친 질문 한 문장(21~28자)에 16~25초가 걸렸다. 브라우저는 15초 뒤 내장 음성으로 넘어가므로 면접은 이어지지만, 실시간으로 쓰려면 GPU 서버가 필요하다. 받아쓰기에서 "쿼리"가 "퀄이", "지원자님"이 "지원자닉"으로 나온 발음 문제도 남아 있다.
- **같이 겪은 환경 문제**: 작업 폴더에 예전에 만든 `av.py`가 있어서 faster-whisper가 쓰는 `av` 패키지 대신 그 파일을 불러왔다. 스크립트를 별도 폴더로 옮기고 `python -I`로 실행해 해결했다.
- **재발 방지**: 들어 보지 못한 음성은 받아쓰기와 음높이로 확인한 뒤에 쓴다. 목소리 설계 결과는 시드마다 다르니 후보를 여러 개 만들어 고른다.

## 27. [외부 API] Pixazo의 VoxCPM2 API가 502를 돌려줌 (미해결)

- **증상**: GPU 없이 VoxCPM2를 쓰려고 Pixazo의 음성 복제 API(`gateway.pixazo.ai/voxcpm/v1/voice-cloning`)를 연결했다. 키 없이 한 번 호출해 보니 401이 아니라 pixazo.ai의 "502: Bad gateway" 페이지가 왔다.
- **원인**: 확인하지 못했다. 이 환경의 프록시 오류가 아니라 Pixazo 쪽 응답이다. 서비스 장애인지, 키 없는 요청을 이렇게 처리하는지는 키로 다시 호출해야 알 수 있다.
- **디버깅**: 공식 데모(Hugging Face Space)는 GPU 없는 기본 CPU로 돌고 있어 대안이 되지 못했다. fal, Replicate, SiliconFlow에서는 VoxCPM2를 찾지 못했다.
- **현재 상태**: 코드는 Pixazo 응답 형식(공식 문서 기준)대로 만들고 가짜 응답으로 테스트했다. 실제 호출은 키를 받은 뒤 확인한다. VoxCPM이 실패하면 다음 TTS(현재 이 환경에서는 Typecast가 정상)로 넘어가므로 면접 음성은 끊기지 않는다.

## 28. [외부 API] Typecast 무료 계정이 면접 한 번을 버티지 못함 (미해결)

- **증상**: 14번 차단이 풀린 뒤 Typecast로 면접관 4명 음성을 3초 간격으로 하나씩 만들고(정상), 이어서 브라우저로 면접을 진행했다. 안내 직원 호명과 위원장 인사까지 읽은 뒤 세 번째 문장부터 `UNUSUAL_ACTIVITY_DETECTED`(403)가 왔다. 3~4분 사이 성공한 요청은 6건이었다.
- **원인**: Typecast가 무료 계정의 짧은 시간 내 반복 요청을 막는 것으로 보인다. 정확한 기준은 공개된 자료에서 찾지 못했다. 면접 한 번은 호명, 인사, 질문, 반응 문장마다 음성을 요청해 1분에 10건 안팎이 나간다.
- **디버깅**: 면접 화면에서 `/api/tts` 응답과 서버 로그를 함께 기록했다. 차단 뒤에는 10분 건너뛰기 규칙대로 ElevenLabs(무료 플랜이라 기본 목소리)가 이어 읽었고, 오디오 재생 7회, 브라우저 음성 0회로 면접 음성은 끊기지 않았다.
- **현재 상태**: 미해결. Typecast 유료 플랜이나, 면접당 음성 요청 수를 줄이는 방법(같은 면접관의 반응과 다음 질문을 한 번에 읽기 등)이 필요하다.
- **같이 고친 것**: 목 면접관이 "4년간 결산을 맡았습니다"에 "네, 4년까지 말씀해 주셔서 이해가 됩니다"라고 반응했다. 기간은 결과 수치가 아니므로 반응에 쓰지 않도록 했다.

## 29. [외부 API] Fish Audio가 "API 크레딧 부족"이었던 이유: 무료 모델을 지정하지 않음

- **증상**: Fish Audio 키로 호출하면 402 `Insufficient API credit`가 왔다. 사용자는 같은 Fish Audio를 다른 곳에서 무료로 쓰고 있었다.
- **원인**: Fish Audio는 API에 무료 모델 `s2.1-pro-free`(요금 0원, 공정 사용)를 두고 있는데, 서버가 모델을 지정하지 않아 유료 기본 모델로 요청했다. 공식 요금표에서 `s2.1-pro-free`가 0원인 것을 확인했다. TTS의 모델 지정 방식은 문서에 없어서, 이미 쓰던 `model` 헤더에 넣어 한 번 호출해 확인했다(성공, 2.9초).
- **해결**: 모델 기본값을 `s2.1-pro-free`로 바꾸고, 무료로 면접 한 번을 끝까지 읽을 수 있는 Fish를 유료 서비스보다 먼저 시도하게 했다(`TTS_ORDER`로 변경 가능). 안내 직원 목소리가 위원장과 같은 ID였어서 다른 여성 목소리(음높이 258Hz)로 바꿨다. 실존 연예인을 흉내 낸 목소리는 후보에서 뺐다. 브라우저로 면접 3문항을 진행해 호명부터 7문장이 모두 Fish로 나온 것을 확인했다(실패 0, 브라우저 음성 0).
- **같이 겪은 환경 문제**: 첫 확인에서 `/api/health`가 여전히 `typecast`라고 답했다. 이전 시험 서버를 `npx tsx`로 띄우고 그 PID를 kill했는데, npx만 종료되고 실제 node 프로세스가 포트를 잡고 있었다. 새 서버는 `EADDRINUSE`로 뜨지 못했다. 남은 프로세스를 PID로 끄고, 이후로는 `node --import tsx`로 직접 띄운다(CLAUDE.md에 추가).
- **재발 방지**: 외부 서비스가 "크레딧 부족"이면 결제 전에 무료 모델·요금제를 먼저 확인한다. 서버를 다시 띄우면 `/api/health`로 새 코드가 돌고 있는지 확인한다.
