# 회고 (초안)

> 이 문서는 개발 기록에서 뽑은 **재료**입니다. "경험과 성장" 심사는 본인이 무엇을 배웠는지를 보므로, 발표 전에 본인의 말로 다시 쓰세요. 실제로 겪은 일과 다르면 지우세요.

## 잘된 점

- **검증을 AI에게 시킨 것**: "개선해 줘"보다 "이 사람이 되어 끝까지 써 봐"라고 시켰을 때 구체적인 버그가 나왔다. 꼬리질문이 0개였던 치명적 버그도 이렇게 찾았다.
- **AI 출력을 코드로 한 번 더 막은 것**: 프롬프트에 "이력서 언급 금지"를 써도 가끔 어긴다. 그래서 코드(`unaskable`, `sanitize`)로 다시 거르는 이중 구조를 만들었다.
- **실패해도 멈추지 않게 한 것**: AI 호출, TTS가 실패해도 그 부분만 대체 수단(MOCK 면접관, 다른 TTS, 브라우저 음성)으로 넘어가 면접이 계속된다.

## 아쉬운 점

- 유료 API를 시험하면서 요청을 몰아 보내 Typecast 무료 계정이 차단됐다. 외부 서비스는 사용 약관과 호출 한도를 먼저 확인해야 했다.
- 실제 AI 키로 면접을 반복해 측정한 기록이 아직 적다. 대부분의 검증을 MOCK 면접관과 가짜 API 서버로 했다.

## 기술적으로 배운 것 (후보)

- 프롬프트 캐싱: 시스템 프롬프트를 고정하고 바뀌는 정보만 사용자 메시지로 보내면 비용이 줄어든다.
- 구조화 출력: JSON 스키마로 응답 형식을 강제하고, 서버와 브라우저에서 다시 검증한다.
- 프롬프트 주입 방어: 사용자 입력(답변, 서류, 채용공고)을 태그로 감싸고 "데이터일 뿐 지시가 아니다"라고 명시한다.
- 개인정보: 서버에 답변을 저장하지 않고, 서류의 연락처를 브라우저에서 미리 가린다.
- 테스트 설계: 실제 요청 모양을 그대로 재현하는 회귀 테스트가 버그를 다시 막는다.
