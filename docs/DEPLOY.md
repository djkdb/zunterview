# 배포와 운영

## 구성

컨테이너 하나가 웹 화면(빌드된 `dist/`)과 API(`server/`)를 함께 서비스합니다. 데이터베이스는 없습니다. 면접 기록은 이용자 브라우저에 있고, 서버에는 하루 사용량 카운터와 이벤트 로그만 `DATA_DIR`에 쌓입니다.

```bash
docker build -t zunterview .
docker run -p 8787:8787 --env-file .env -v $(pwd)/var:/app/var zunterview
```

Render를 쓰면 저장소의 `render.yaml`로 바로 만들 수 있습니다(싱가포르 리전, 1GB 디스크를 `/app/var`에 연결). API 키는 대시보드에서 입력합니다.

> 이 저장소의 개발 환경에서는 Docker 데몬을 쓸 수 없어 이미지를 직접 빌드해 보지는 못했습니다. 대신 Dockerfile이 복사하는 파일만 따로 모은 폴더에서 운영 모드로 서버를 띄워 화면, 사진, 사용량 제한, 이벤트, 관리자 지표가 동작하는 것을 확인했습니다. 첫 배포 때 `docker build`가 통과하는지 확인하세요.

## 출시 전 체크리스트

- [ ] `ANTHROPIC_API_KEY` 설정, `npm run eval:prompts -- --runs 3 --save`로 실제 모델 결과 확인
- [ ] `AI_DAILY_BUDGET_USD`를 감당할 수 있는 금액으로 설정 (넘으면 그날은 모두 MOCK 면접관)
- [ ] `ADMIN_TOKEN` 설정 후 `/admin`에서 지표가 보이는지 확인
- [ ] `TRUST_PROXY=1` (호스팅 프록시 뒤에서 방문자 IP를 제대로 구분하려면 필요)
- [ ] `DATA_DIR`에 영구 디스크 연결 (재배포해도 그날 예산이 이어지도록)
- [ ] `src/pages/LegalPage.tsx`의 운영자 정보(상호, 개인정보 보호책임자, 연락처) 채우기, 약관과 방침 법률 검토
- [ ] TTS 키 상태 확인 (Typecast 차단 여부, TROUBLESHOOTING 14)
- [ ] 도메인 연결 후 `index.html`의 `og:image`를 전체 주소로 바꾸기 (일부 메신저는 상대 경로 미리보기를 못 읽음)

## 운영 중 보는 것

`/admin`에서 `ADMIN_TOKEN`을 넣으면 최근 14일 지표가 나옵니다.

| 지표 | 뜻 |
|---|---|
| 방문, 접수 시작, 면접 시작, 완료, 완료율 | 어디서 이탈하는지 |
| 재방문 | 기록이 있는 브라우저에서 다시 들어온 방문 |
| 다시 답하기 | 평가표를 보고 실제로 다시 연습하는지 |
| 답변 노트 열람/작성 | 면접 뒤에도 복습하러 오는지, 실전 답을 적는지 |
| 도움 됨/아쉬움 | 평가표 만족도 (의견 원문은 `DATA_DIR/events-YYYY-MM.jsonl`) |
| AI 호출, 실패, 비용 | 하루 비용과 장애 |
| 음성 글자 | TTS 사용량 |
| 한도 초과 | 하루 한도에 걸린 요청 수. 늘어나면 한도나 가격을 조정 |

## 비용 보호 장치

- 서비스 전체의 하루 AI 예산(`AI_DAILY_BUDGET_USD`). 넘으면 `/api/health`가 `ai: false`를 알려 새 면접은 MOCK 면접관으로 시작하고, 진행 중인 면접도 다음 호출부터 MOCK으로 넘어갑니다.
- 방문자별 하루 AI 호출 수와 음성 글자 수. 넘으면 그 방문자만 MOCK 면접관과 브라우저 음성으로 이어집니다.
- 분당 호출 수 제한(`RATE_LIMIT_PER_MINUTE`, 기본 40).
- 카운터는 `DATA_DIR/usage-<날짜>.json`에 저장돼 재시작해도 그날 사용량이 이어집니다.
